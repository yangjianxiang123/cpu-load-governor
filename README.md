# CPU Load Governor

> 由 Miracles 制作的一款简单小玩意
>
> 指定一个 CPU 占用率（比如 50%），程序自动把系统负载稳定在这个数值附近。
> 界面为整窗自绘 · 毛玻璃质感 · 支持换肤与自定义壁纸。

## 这是什么

一个 Windows 上的小工具。拖动滑块设定目标值，点「启动」后，
程序会开若干后台线程精确控制 CPU 负载，让**系统总占用率**稳定在你设定的数值。

和常见的「烤机软件」不同，它的重点不是把 CPU 跑满，而是**精确可控**：
你设 50%，它就守在 50% —— 高了就减、低了就加。

## 功能

| 功能 | 说明 |
|---|---|
| 精确控载 | 目标 0~100% 任意设定，自动收敛并保持稳定 |

到 [Releases](../../releases/latest) 页面下载 **`CpuLoadGovernor.exe`**，双击运行即可，无需安装任何东西。


```bash

  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true \
  -o 发布
```

## 工作原理

### 1. 怎么把占用率控制在指定值

用的是**占空比（duty cycle）**的思路。把时间切成 50 毫秒一个周期，每个周期内：

```
├──── 忙（满负荷计算）────┼──── 闲（Thread.Sleep）────┤
        占 50%                   占 50%
```

忙的时间占整个周期的比例，就等于 CPU 的平均占用率。
50ms 足够短，任务管理器看起来就是一条平稳的直线。

因为一个线程只能跑满一个核心，所以按 CPU 核心数开对应数量的线程。

### 2. 怎么保证「稳定」而不是「大概」

外部每 0.5 秒采样一次真实占用率，和目标值比较：

```csharp
double err = _targetPct - usage;                              // 差多少
_contributionPct = Math.Clamp(_contributionPct + err * 0.4, 0, 100);
```

原理和空调恒温器一样 —— 低了就加、高了就减，每次只调整差距的一部分，
避免调过头来回震荡。

### 3. CPU 占用率怎么读出来

Windows 不直接提供「当前占用率」，只提供三个**自开机以来的累计时间**：
空闲时间、内核态时间、用户态时间。

所以要采两次样，用差值计算：

```
占用率 = (总时间增量 - 空闲增量) / 总时间增量 × 100%
```

这也解释了为什么第一次采样只能返回 0 —— 还没有「上一次」可以比较。

### 4. 界面为什么不用 WinForms 控件

没有用 `Button`、`Slider` 这些现成控件，而是**把整个窗口当一张画布**，
所有元素都自己画（`OnPaint` 里一次性画完）。

原因：现成控件太多时，切换主题需要重绘十几次，会明显卡顿；
自己画则每次重绘只需一遍。实测帧率从 **6 FPS 提升到约 65 FPS**。

代价是按钮点击、滑块拖动都要自己算坐标（见 `HitTest` 方法）。

### 5. 毛玻璃效果怎么做

没有用真正的高斯模糊（逐像素处理太慢）。而是分四层叠加模拟：

1. **模糊背衬** —— 把壁纸缩到 24×20 再放大，用插值产生柔和扩散
2. **半透明着色** —— 盖一层带透明度的主题色，决定「通透度」
3. **顶部高光** —— 上半部加白色渐变，模拟光线反射
4. **边缘描边** —— 上左偏亮、下右偏暗，制造玻璃的厚度感

## 常见问题

**Q：杀毒软件报毒？**
单文件自解压的 exe 偶尔会被误报，添加信任即可。这是打包方式的常见现象，
可以自己从源码编译验证。

**Q：为什么 exe 有 49 MB？**
因为把 .NET 运行时（约 40 MB）一起打包了，这样对方不用装任何东西就能运行。
如果你确定目标电脑装了 .NET 10，可以去掉 `--self-contained true`，
体积会降到约 200 KB。

**Q：设置存在哪？**
`C:\Users\你的用户名\AppData\Roaming\CpuLoadGui\config.ini`

**Q：会影响电脑吗？**
不会。负载完全由程序自己的线程产生，点「停止」会立刻结束所有线程。
程序关闭时也会自动清理。
